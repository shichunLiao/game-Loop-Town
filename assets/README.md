# 资源库说明（assets / data/assets）

本文件写给**美术与关卡设计**：每类资源放在哪、叫什么、怎么替换、在哪能看到它。

---

## 一、为什么要有 `data/assets/`

原先 `assets/` 下只有一堆 PNG，编辑器里点开一张图只能看到像素，
看不出「这是谁、多少帧、多大、干什么用」，也只能按 F5 跑到游戏里才见到效果。

现在每个资源都有一份**定义文件**（Godot Resource），在编辑器里双击就能看到
贴图预览、帧数、尺寸、用途说明：

| 定义 | 位置 | 编辑器里能看到什么 |
|---|---|---|
| 角色 | `data/assets/actors/<id>.tres` | 全部动画条目（贴图 + 帧数）、单帧尺寸、碰撞体型、状态列表、美术说明 |
| 环境层 | `data/assets/environments/<map_id>.tres` | 每层背景的大图预览、视差系数、垂直偏移、透明度 |
| 道具 | `data/assets/props/<id>.tres` | 图标预览、边长、**用途说明**（判断该画多细） |
| 总清单 | `data/assets/manifest.json` | 全部资源的机器可读索引（角色 5 / 环境 13 / 道具 12 / 特效 4 / UI 4 / 音频 51） |

这些定义是**运行时真正读取的**，不是文档：`LevelLoader` 从环境层定义生成视差背景，
`ActorFactory` 从角色定义生成 SpriteFrames。改了定义，游戏立刻变。

## 二、目录分类

```
assets/
├── characters/player/   主角 9 个动作的图集（64×64/帧）
├── enemies/             敌人与 Boss（蜡像 64、镇民 64、莫里斯 128、孩童幽灵 64）
├── environments/        背景视差层（1920×1080）
├── props/               道具与场景物（32 或 64）
├── ui/                  HUD 元件（面板 / 生命容器 / 帽子图标）
├── vfx/                 特效（命中火花 / 闪白 / 交互标记 / 危险标记）
└── audio/
    ├── sfx/             30 个音效
    ├── music/           10 首区域音乐（无缝循环 24s）
    └── ambient/         11 个环境声（无缝循环 20s）

comscene/                小镇图块集 224 张 32×32（外部素材包，未接入 TileMapLayer）
```

## 三、命名规则

| 类型 | 规则 | 例子 |
|---|---|---|
| 角色图集 | `<角色>_<动作>.png`，横向平铺，帧宽=图宽÷帧数 | `player_run.png`（8 帧）、`morris_death.png`（8 帧 ×128） |
| 背景层 | `bg_<场景>_<远近>.png`，`far`/`mid`/`near` 表示由远及近 | `bg_town_far.png`、`bg_wax_lane.png` |
| 音效 | `sfx_<用途>.wav` | `sfx_bell.wav`、`sfx_wax_crack.wav` |
| 音乐 | `mus_<区域>.wav` | `mus_clocktower.wav` |
| 环境声 | `amb_<区域>[_<世界状态>].wav` | `amb_town_night.wav` |
| 道具 | 名词小写，单词用下划线 | `rag_doll.png`、`big_scissors.png` |

## 四、替换成正式素材

**不需要改任何代码。** 覆盖同名文件即可，但要注意两件事：

1. **帧数变了** → 改对应的 `data/assets/actors/<id>.tres` 里的 `frames` 数字。
   校验脚本会检查「图集宽度能否被帧数整除」，写错会直接报错。
2. **帧尺寸变了** → 改 `frame_size`，同时按新尺寸调整 `body_size`（碰撞胶囊）。

改完跑一次：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev\run_all_tests.ps1
```

第一项就是资源校验，会逐条检查：
贴图能否取到、图宽能否被帧数整除、道具是否有用途说明、总清单是否完整。

## 五、当前美术状态（必须知道）

**全部是程序化占位图**，由 `tools/generate_placeholder_art.py` 生成（Pillow 绘制，
4× 超采样后降采样）。它们**风格统一、接口稳定**，但**远未达到参考图的丰富度**——

参考图那种手绘质感（笔触、有机形状、真实光影过渡）**无法用代码图元画出来**。
要达到那个水平需要真正的手绘或 AI 生成素材，替换方式见上一节。

替换时的优先级建议：

1. **主角 9 个动作** —— 玩家看得最久
2. **莫里斯 5 个动作** —— 第一章 Boss，且**眼里必须有琥珀色高光**
   （替身没有高光，这是二阶段解谜的唯一线索，换图时不能丢）
3. **蜡像敌人** —— **必须保持没有眼睛**，同理
4. 背景三层 —— 每张地图 3 张 1920×1080，工作量最大但提升最明显
5. 道具与 UI

## 六、设计锚点（换素材时不能丢的特征）

这些不是审美偏好，是玩法与叙事依赖的：

| 资源 | 必须保留的特征 | 原因 |
|---|---|---|
| 主角 | 巨大侦探帽、右脸烧伤疤痕、纸白笔记本、帽檐下只有琥珀色眼高光 | 文档【四】角色设定；看不见脸是叙事核心 |
| 莫里斯 | 右脸黑色烧伤印记、**眼里有琥珀高光**、全镇唯一穿彩色衣服 | 二阶段「识别真身」解谜 |
| 蜡像替身 | 与真身同外形、**没有眼高光** | 同上 |
| 蜡像敌人 | **没有眼睛**、边缘融化滴落 | 玩家先在蜡像巷学会「假人没眼睛」 |
| 镇民 | 灰衣 | 全镇只有莫里斯穿彩色 |
| 小铃布偶 | **全场唯一没有破损的布偶**，干净、双马尾、两只眼睛都在 | 第五章后重读：她是唯一「完整」的 |
| 记忆碎片 | 暖黄浮动光点 | 与暗环境拉开，一眼可辨 |
| 战斗单位 | 上方暗红菱形 | 与装饰蜡像区分 |
